# MAQAN — социальная и мировая симуляция: интеграционный контракт

## Архитектурные инварианты

1. `CharacterRegistry` остаётся единственным источником личности NPC. Все долгоживущие социальные, профессиональные, семейные и военные данные привязываются к существующему `Character.id` и/или `Character.props`.
2. Minecraft Entity, TroopEntity, Worker и другие физические/рабочие объекты являются проекциями или назначениями персонажа, а не новыми личностями. Для солдата используется существующий `TroopEntity.characterId`.
3. `CharacterRegistry` публикует жизненные события и хранит ограниченную историю последних 64 переходов непосредственно в props персонажа. Восстановление сохранения уведомляет подписчиков, но не добавляет фиктивное событие в историю.
4. Фактическая репутация отделена от знаний конкретного NPC. Отсутствие знания не равно нейтральной репутации.
5. Репутация имеет области WORLD, SETTLEMENT, POLITY и ORGANIZATION. Передача между областями возможна только по явным связям с коэффициентом от -1 до +1.
6. Слухи передаются через адаптер реального социального графа. Географическая близость или принадлежность к тому же миру сами по себе не создают знания.

## Реализованная основа в текущей ветке

- `ReputationStore`: scoped values, явные союзные/враждебные коэффициенты, индивидуальные наблюдения, источник, время, confidence и глубина передачи; сохранение значений, связей, названий и знаний.
- `ReputationStore.witness`: меняет реальную репутацию в указанной области и фиксирует результат только для свидетеля.
- `shareWithinOrganization`: передача только при подтверждённом членстве получателя; ограничены возраст сообщения, глубина и минимальная уверенность.
- `shareWithTrustedContact`: личная передача конкретному доверенному контакту с ослаблением уверенности и увеличением глубины слуха.
- `knownAt`: позволяет отсеивать устаревшие/недостоверные сведения; старое знание не маскируется под актуальное.
- `RumorNetwork`: детерминированная ограниченная доставка через переданный контактный граф, с проверкой доступности связи и членства; не запускает рекурсивную массовую рассылку в одном проходе.
- Диалоговый мост: ветвления по знанию конкретного говорящего NPC через `rep_known`, `known_rep_at_least`, `known_rep_at_most`, `known_standing_is`.
- `CharacterRegistry`: единая ограниченная история жизненных событий в Character.props и exactly-once публикация события слушателям.
- `CharacterDevelopment`, `DialogueMemory`, `ResidentSocial`, `ResidentEquipment`, `ArmyHierarchy`, `TroopEntity.characterId`, `TroopProgression`, `Morale`, `OperationalSupply` остаются существующими подсистемами и не заменяются параллельными реестрами.

## Границы, которые нельзя объявлять завершёнными

- Автоматическое обнаружение преступлений и определение свидетелей в игровом мире ещё должно быть подключено к событиям урона, кражи, нападения, нарушения закона и охраны.
- Реальный поставщик социального графа для `RumorNetwork` должен читать знакомства/отношения, общие организации, текущую доступность связи, дипломатические каналы и ограничения мира. Сам сервис не придумывает контактов.
- Дипломатическое распространение между союзными государствами и целенаправленное использование слухов разведкой/вражескими образованиями требуют адаптеров дипломатии и интриги.
- Влияние репутации на итоговую цену покупки/продажи, найм, генерацию и принятие заданий, городской доступ, задержание и дипломатические решения должно быть подключено к авторитетным операциям соответствующих модулей. Одних диалоговых условий недостаточно.
- Личная история солдата, ранения, дисциплинарные взыскания, жалованье и снабжение должны записываться в тот же Character ID при фактическом изменении военного состояния.
- Character Development нуждается в data-driven реестрах рас/классов/способностей и валидируемых правилах прогрессии; произвольные строки в props сами по себе не доказывают завершённую игровую систему.
- Сквозная симуляция должна иметь игровые интеграционные тесты и проверку сохранения/загрузки, а не только чистые unit-тесты.

## Правила дальнейших интеграций

- Не создавать второй Character Registry и не дублировать Character ID внутри поселений, армии, диалогов или семей.
- Не распространять локальную репутацию автоматически на весь мир.
- Любое событие должно иметь источник, область, время и идемпотентный идентификатор до повторяемой доставки/обработки.
- Любое экономическое/социальное последствие применяется только после успешной авторитетной операции; текст диалога не считается подтверждением транзакции.
- Для слухов сохраняются provenance, confidence, depth и время; пересказ не должен повышать достоверность.
- Не объявлять игровые функции готовыми по наличию API или unit-теста без подключения Minecraft runtime.
